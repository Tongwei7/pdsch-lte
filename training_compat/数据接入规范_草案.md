# 数据接入规范（草案，非最终仿真格式）

这份规范是神经网络工程的显式接入提案。当前正在运行的“规划 LTE 仿真数据集生成”对话仍在分析实测特征，没有定稿最终训练数据格式，也未生成可验收的大规模训练集。本文不能被当作那个对话已经确认的最终格式。

历史仿真代码和旧数据已按用户要求删除。本工程不包含历史格式读取器、不读取历史批次，也不会靠数组尺寸猜测旧格式。最终生成器可以实现此提案，或在格式确定后单独编写适配器。

## 一、任务与信任边界

目标是目标小区全部 PDSCH 的资源占用，包括承载公共系统信息的 PDSCH；输出不表示用户身份。普通用户 RNTI、真实 DCI、理想信道、发送网格、真实分配等不能作为网络输入。

系统入口是原始接收 IQ。神经网络入口是经传统前端完成载波居中、同步、残余频偏校正和 OFDM 解调后的复数资源格；前端必须使用实际接收观测和公共信息。网络包本身不执行时域 IQ 的完整 LTE 捕获，不能直接把原始二进制 IQ 文件当作下述资源格文件。

## 二、每个分块的数组

文件可以是 NumPy `.npz`，或 MATLAB `save(...,'-v7')` 导出的 `.mat`。当前未约定 HDF5 的轴序与元数据，不宣称兼容任意 `-v7.3` 文件。MATLAB 可以省略尾部单例维度，其他轴不能交换。

| 名称 | 类型和形状 | 意义 |
|---|---|---|
| rx_real | float32 `[K,L,R,S]` | OFDM 解调后的接收网格实部 |
| rx_imag | float32 `[K,L,R,S]` | 对应虚部 |
| subframe_index | int64 `[S]`，MATLAB 行/列向量均可 | 相对整次捕获起点的子帧编号，递增，可显式存在缺失 |
| label_re | 0/1 `[K,L,S]` | 发送端真实 PDSCH 数据 RE 占用，仅训练/评价需要 |
| label_prb | 0/1 `[K/12,S]` | 每个子帧的 PRB 占用，仅训练/评价需要 |
| public_excluded | 可选，0/1 `[K,L,S]` | 经接收端公共信息确认的非 PDSCH 位置 |
| public_valid | 与上一项同时提供，0/1 `[K,L,S]` | 公共位置图有效性，未知位置为 0 |

`K=12×PRB数`；`L=14`（正常 CP）或 `12`（扩展 CP）；`R` 是真正同步采集的接收支路数；`S` 是分块内子帧数。频率轴从低到高，只含有效子载波，不含 FFT 的 DC。时间轴为子帧内 OFDM 符号。`label_prb` 必须与该 PRB 对应的 PDSCH 数据 RE 并集一致。

参考信号位置在精确 `label_re` 中通常为 0，而包含这些参考信号的 PRB 仍可能在 `label_prb` 中为 1。发射天线维度需要在标签生成侧按任务定义合并，不能把接收支路数当作发射端口或数据层数。

公共位置图必须来自实际恢复的信息，不能用发送端的真实候选图伪装。缺失时两个图均视为未知，不根据标签生成。当前这些图仅作为可选特征，不硬性删除网络输出。

带宽、PCI、采样率、载波位置、CP、同步估计、种子、传播场景、标签来源和公共先验来源应在生成器的审计元数据另存；它们不自动成为网络输入。标签来源必须可追溯，能量门限和解码成功样本集合不能替代完整占用真值。

## 三、清单 manifest.csv

```csv
schema,path,split,group_id,alignment_valid
pdsch-occupancy-proposal-v1,train/capture_001.mat,train,scenario_family_001,1
pdsch-occupancy-proposal-v1,validation/capture_002.mat,validation,scenario_family_002,1
pdsch-occupancy-proposal-v1,test/capture_003.mat,test,scenario_family_003,1
```

`path` 相对清单位置，也可使用明确的绝对路径；`split` 为 train/validation/test。`group_id` 应覆盖同一连续捕获、共享随机实现或同源加噪/损伤变体，使同组不跨集合。仅给每个窗口随意起新 group_id 不能防泄漏。同步或标签对齐失败的分块标记 `alignment_valid=0`，不参加监督训练，但计入拒绝统计；文件仍应存在以保存拒绝证据。

每个分块建议保存几十到几百毫秒，先测试读取效率。当前 MAT/NPZ 读取以分块为单位，缓存最多两个分块；不要将 TB 级连续数据做成单个文件。后续确需 HDF5 随机访问时另设版本化适配器。

## 四、窗口与坐标

默认将连续 10 个子帧构成一个 10 ms 窗口，训练步长也是 10。窗口不会跨分块，遇到编号不连续就拒绝该窗口。少于一个完整窗口的部分不补造训练标签，检查报告提供使用与未使用数量。

这里的 10 ms 窗口未必对齐无线帧边界。`subframe_index` 是捕获相对编号，输出 `frame_ordinal` 也只是相对分组，不是广播得到的系统帧号 SFN；需要绝对帧号时应由前端额外维护坐标映射。

默认只使用第一条实际接收支路，输入顺序为 I、Q、对数功率；`--rx all` 保留所有支路，要求训练/验证/部署支路数一致。`--public` 追加排除图、有效图。`--mode power` 可以做仅功率特征对照。

归一化只从训练窗口拟合并保存到检查点。I/Q 使用共同缩放并保持零中心定义，功率使用训练统计；公共二值图不标准化。验证、测试、推理复用该状态。

## 五、MATLAB 导出示意

下面仅展示字段保存方式，**不是 LTE 仿真生成器**。变量需由未来确认的发送/传播/接收链路产生。

```matlab
% rxGrid 必须已明确整理成 K × L × R × S；不得直接将时域 IQ reshape 冒充。
rx_real = single(real(rxGrid));
rx_imag = single(imag(rxGrid));
% label_re、label_prb 来自可信发送映射；subframe_index 来自坐标对齐。
save(outputFile,'rx_real','rx_imag','label_re','label_prb', ...
     'subframe_index','-v7');
```
